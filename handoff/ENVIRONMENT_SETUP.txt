================================================================================
BETGENIUS MLB PHASE 1 -- ENVIRONMENT SETUP
================================================================================

GOAL: get from this ZIP to a passing smoke test, then to a full reproduction of
the 6/11 result, with no credentials and no network access.

THE REFERENCE ENVIRONMENT -- what the shipped numbers were produced on:
    OS              Windows 11 Pro (10.0.26200)
    Python          3.14.6
    numpy           2.4.6
    pandas          3.0.3
    scikit-learn    1.9.0
    scipy           1.18.0
    statsmodels     0.14.6
    Deno            2.9.6  (TypeScript 6.0.3)
    Node            24.20.0

The pipeline is pure Python and runs on macOS and Linux equally well. Deno and
Node are needed only for the warehouse export and the frontend app.


================================================================================
1. WINDOWS
================================================================================

1.1 PYTHON
    Install 3.11 or newer (3.14.6 is the reference) from python.org or the
    Microsoft Store. Tick "Add python.exe to PATH".

    python --version

1.2 CREATE AND ACTIVATE A VIRTUAL ENVIRONMENT
    cd <extracted>\BetGenius_Client_Handoff_Final\project\betgenius
    python -m venv .venv
    .venv\Scripts\Activate.ps1

    If PowerShell refuses with an execution-policy error:
        Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass

1.3 INSTALL
    pip install --upgrade pip
    pip install -r requirements.txt

1.4 SET THE THREE PATH VARIABLES (PowerShell)
    $env:UPLIFT_DATA_DIR  = "$PWD\harness\uplift\data_expanded_6h"
    $env:UPLIFT_CACHE_DIR = "$PWD\harness\uplift\cache_fam"
    $env:UPLIFT_MEMBERS   = "rf,et,gbmB,gbmC,gbmD"

    THESE ARE NOT OPTIONAL. Without UPLIFT_DATA_DIR the code looks for a dataset
    that is not in this package.

1.5 NODE AND DENO -- ONLY IF YOU WILL TOUCH THE APP OR RE-EXPORT THE WAREHOUSE
    Node:  https://nodejs.org  (24.x)
    Deno:  irm https://deno.land/install.ps1 | iex
    $env:DENO_CERT = "$PWD\prod-ca-2021.crt"

7. DATABASE
================================================================================
NOT REQUIRED to reproduce the result. The data snapshot ships with this package.

It is required only to regenerate data from source, and then only for SELECT:
    HARNESS_DATABASE_URL   a `harness_readonly` Postgres role
                           (SELECT only, connection limit 10)

HARD RULE: never run two harness processes at once -- the role's connection
limit is 10 and the sweep scripts sequence markets for this reason.

EXPECTED FROM run_final_model.py:

        confidence floor=60  ladder collapse=maxEv
    per-market member overrides adopted on SELECT (of 11 markets): 2
        spreads              -> price
        batter_total_bases   -> rf
    PASS on the untouched VERDICT window : 6 / 11
    PASS on the full out-of-sample period: 7 / 11
    PASS on BOTH gates                   : 6 / 11
    units on the verdict window: 202.7   |   units full OOS: 559.3

Then compare:
    diff harness/uplift/reports/final_v1.csv ../../results/final_v1.csv

On a matching environment this is byte-identical. On a different CPU, BLAS build
or library version, expect agreement well inside a basis point but not an
identical hash -- scikit-learn floating point is not guaranteed portable. Every
shipped file's sha256 is in reports/reproducibility.txt.


================================================================================
13. DISK, MEMORY AND TIME
================================================================================
    Extracted package        ~340 MB (329 MB of it is the data snapshot)
    Member cache once built  ~940 MB
    Total working space      ~1.5 GB
    Peak RAM                 comfortably under 8 GB; the largest single market
                             is 120,269 rows x 47 features
    Cache build              ~90 minutes, single-threaded
    Main run                 ~5 minutes from a warm cache
    Live board               ~10 minutes
    Full robustness suite    several hours (it rebuilds a cache per variant)

Everything is CPU-only and single-threaded by design -- `n_jobs=1` is set
explicitly on the forests so a re-run is stable.


================================================================================
14. IF SOMETHING GOES WRONG
================================================================================
PRODUCTION_SETUP.txt section 14 is the troubleshooting table. The three most
common problems:

    ~413k graded rows instead of ~530k   UPLIFT_DATA_DIR is unset.
    "not in cache: <markets>"            UPLIFT_CACHE_DIR is wrong, or the cache
                                         has not been built yet.
    overrides missing / `rf` absent      the cache was built without
                                         UPLIFT_MEMBERS.
