4. WHAT IS DETERMINISTIC AND WHAT IS NOT
--------------------------------------------------------------------------------
DETERMINISTIC, VERIFIED BY RE-RUN
  * The whole result stage from the member cache onward: board construction,
    grading, bootstrap CIs, the override rule, the global sweep, the final
    table. Verified bit-identical above.
  * The bootstrap: seeded at 20260701 (mlbgate.bootstrap_mean_ci) and drawn
    from numpy PCG64, or from a line-for-line port of the shipped mulberry32
    stream when exact=True.

DETERMINISTIC BY CONSTRUCTION, NOT RE-VERIFIED IN THIS AUDIT
  * The member cache itself. Every estimator carries a fixed random_state
    (HistGradientBoosting 20260916; RandomForest / ExtraTrees 20260917) and the
    walk-forward fold boundaries are timestamps derived from the data, not
    random draws. Rebuilding the cache takes roughly 90 minutes on this machine
    and was NOT repeated here; the validation report states that the earlier _v1
    cache did rebuild member-for-member identically after the frames.py and
    policy.py edits, and that claim is carried forward rather than re-measured.
    A client who wants it verified should run section 6's rebuild and diff
    reports/final_v1.csv again.

NOT BIT-REPRODUCIBLE ACROSS MACHINES
  * Floating-point results from scikit-learn are not guaranteed identical
    across different BLAS builds, CPU architectures or library versions. The
    pinned versions in configs/requirements.txt are the ones the shipped numbers
    were produced with. Expect ROI to agree to well within a basis point on a
    matching environment; do not expect identical sha256 on a different one.

NOT REPRODUCIBLE AT ALL FROM THIS PACKAGE
  * Anything that re-pulls from The Odds API. The provider serves historical
    odds from 2023-05 only and charges credits; the packaged snapshot removes
    the need, which is why it is included (section 5).

6. HOW A CLIENT REPRODUCES THE TABLE FROM THIS PACKAGE
--------------------------------------------------------------------------------
No network and no API credits are required. From project/betgenius/:

    pip install -r requirements.txt

    # PowerShell
    $env:UPLIFT_DATA_DIR  = "$PWD\harness\uplift\data_expanded_6h"
    $env:UPLIFT_CACHE_DIR = "$PWD\harness\uplift\cache_fam"
    $env:UPLIFT_MEMBERS   = "rf,et,gbmB,gbmC,gbmD"

    # bash
    export UPLIFT_DATA_DIR="$PWD/harness/uplift/data_expanded_6h"
    export UPLIFT_CACHE_DIR="$PWD/harness/uplift/cache_fam"
    export UPLIFT_MEMBERS="rf,et,gbmB,gbmC,gbmD"

    python harness/uplift/build_cache.py          # ~90 min, writes ~940 MB
    python harness/uplift/run_final_model.py --conf=60 --tag=_v1
    python harness/uplift/final_matrix.py --tag=_v1   # needs robustness_v1.csv beside it
    python harness/uplift/parity_audit.py --tag=_v1

Then diff harness/uplift/reports/final_v1.csv against results/final_v1.csv. Every column
should match; see section 4 for what "match" means across machines.

The member cache (cache_fam/, 939 MB) is NOT shipped. It is a pure function of
the shipped data plus the shipped source, and build_cache.py regenerates it.
