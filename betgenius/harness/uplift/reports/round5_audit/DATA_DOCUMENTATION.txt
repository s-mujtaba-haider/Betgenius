--------------------------------------------------------------------------------

      cache_mlb_boxscore_player_stats, via dump_box.ts, read-only against the
      harness_readonly Postgres role. game_date is pulled as ::text ON PURPOSE --

3. ENTRY-PRICE CONVENTION -- READ THIS BEFORE COMPARING ANY NUMBER
--------------------------------------------------------------------------------

The entry price is the earliest snapshot STRICTLY BEFORE first pitch, at the
configured lead. The warehouse's own lead, measured by probe_entry_lead.ts:

      2024-03 -> 2025-10      6.01 h before first pitch
      2026-04 -> 2026-05      1.01 h before first pitch

The warehouse therefore contains a convention break at the 2026 boundary. This
is a property of the production snapshot scheduler, not of any ingest.

All Odds API rows were pulled at 6 h to match the majority convention. This
mattered more than the volume of data:

      entry convention      verdict PASS      both-gates PASS
      T-1h                      2/11                 2
      T-6h                      5/11                 5

RESIDUAL, DISCLOSED: 2026 warehouse rows remain at their native ~1.01 h while
2026 API rows are at 6 h. Normalising it would mean overwriting authoritative
warehouse values, which is not done without a documented reconciliation.

A number produced under a different entry convention is NOT comparable to a
number in this pack.

5. WHAT IS MISSING, AND WHY IT CANNOT BE FIXED FROM HERE
--------------------------------------------------------------------------------

  (a) THE TWELVE-MONTH BOX-SCORE HOLE -- the biggest remaining data defect.
      runs_scored and batter_strikeouts are absent from
      cache_mlb_boxscore_player_stats for a continuous block: 2025-03, then
      2025-06 -> 2026-05, with 2026-06 at 47%. hits / total_bases / rbi are 100%
      throughout. The gap tracks WHEN ROWS WERE WRITTEN: the 2026-05-27/28
      backfill populated a reduced column set.

      Effect: batter_runs_scored covers 2,954 games and batter_strikeouts 1,439,
      against 5,393 for batter_hits, and both markets' verdict windows start
      earlier than the rest.

      *** RE-RUNNING THAT BACKFILL WITH THE FULL COLUMN SET IS THE HIGHEST-VALUE
      PRODUCTION FIX AVAILABLE TO THIS PROJECT. *** It is a write to the
      warehouse and is outside this pack's read-only scope.

      Odds for those dates EXIST. Outcomes do not. A larger n is only obtainable
      by inventing settlements, so the gap is left open.

  (b) 2020-2022 -- the Odds API historical endpoint returns HTTP 422,
      "Historical odds are not available". Confirmed in round 4 and re-confirmed
      2026-09-17. Not a credit limit. Cannot be bought.

  (c) 2023 -- odds ARE served from 2023-05, all 11 markets. But boxscores.csv
      starts 2024-04-01, so no 2023 candidate can be settled. NOT purchased:
      spending credits on ungradeable rows is waste, and fabricating 2023
      outcomes is not an option.

  (d) LINE MOVEMENT / CLV -- the odds dumps hold a single snapshot per
      (event, line). No opening price, no closing price, no per-book detail, no
      snapshot timestamp column. Line movement cannot be reconstructed.
      Capturing it going forward is a standing recommendation.

6. TABLES DELIBERATELY NOT USED
--------------------------------------------------------------------------------

  cache_mlb_historical_lineups (135,324 rows) -- UNUSABLE, LEAK.
      Every row was written AFTER first pitch (minimum +87.5 h, mean +600 days).
      It is the game's own lineup, backfilled, late scratches included. Lineup
      features are built from PRIOR games' box scores instead.

  cache_mlb_historical_weather (7,527 rows, 100% of games) -- EXISTS, NOT USED.
      open-meteo historical is REANALYSIS: the weather that happened, not the
      forecast a bettor had at T-6h. Validating on actuals while production runs
      on forecasts overstates the backtest. Needs a forecast archive or a
      noise-injection study first.

  cache_statcast_* (137k rows) -- genuine daily series, 117 snapshot_dates each
      written same-day, but STARTS 2026-05-20: three months into a 29-month
      evaluation. Too short to gate on. Keep accumulating it -- it is the one
      source that may contain something the book does not fully price.

  cache_mlb_historical_bullpen (13,141 rows) -- ends 2025-10-31, and
      features.bullpen() already rebuilds the same quantities from relief
      box-score lines over the full period. Skipped.

  cache_mlb_player_metadata (1,337 rows) -- bats/throws. Static and safe, and it
      WAS tested (round 3, E19). Rejected on its merits: it added nothing,
      because the book knows the starter and the batter's hand too.

8. POINT-IN-TIME INTEGRITY
--------------------------------------------------------------------------------

  * Every feature roll-up reads box scores from an EARLIER LOCAL CALENDAR DATE
    than the game it feeds. Enforced in frames.asof_rollup.
  * check_asof.py recomputes sampled feature rows the slow way: 0 mismatches --
    AND, the control that makes the test meaningful, 188/200, 179/200 and
    195/200 sampled rows WOULD CHANGE if the game's own day were admitted. A
    test that passes because nothing moves is not a test.
  * Walk-forward fold boundaries are TIMESTAMPS, not row indices, so picks
    sharing a commence time cannot straddle a boundary. That leak alone has
    turned a FAIL into a PASS in this project before.
  * Placebo-lag variants (1d, 3d, 7d) are run on every headline configuration.
    A same-game leak dies at the first day of lag; a form signal does not.
